# Validate

## Объяснение решения

Дано:

- `pushed` — порядок добавления элементов в стек;
- `popped` — порядок, в котором элементы должны быть извлечены из стека.

Надо определить может ли последовательность `popped` получиться из `pushed` с помощью операций `push` и `pop`.
Элементы уникальны.

Для решения используется доп стек `stack`.

Алгоритм:

1. Последовательно берём элементы из `pushed`.
2. Добавляем каждый элемент в стек с помощью `append()`.
3. После каждого добавления проверяем вершину стека.
4. Если вершина стека совпадает с текущим элементом из `popped`, извлекаем её с помощью `pop()`.
5. Переходим к следующему элементу `popped`.
6. После обработки всех элементов проверяем, удалось ли извлечь всю последовательность `popped`.

Идея в том, что из стека можно удалить только элемент, который находится на его вершине.
---

## Оценка сложности

Каждый элемент:
- один раз добавляется в стек;
- не более одного раза удаляется из стека.

| Операция | Время | Доп. память |
|---|---:|---:|
| Добавление элемента в стек | O(1) | O(1) |
| Удаление элемента из стека | O(1) | O(1) |
| Проверка всей последовательности | O(n) | O(n) |

### По времени: O(n)

Не проходим по одним и тем же элементам много раз. Каждый элемент максимум один раз добавляется в стек и один раз удаляется.

### По памяти: O(n)

В худшем случае все элементы могут одновременно находиться в стеке.

## Визуализация работы алгоритма

Общая схема работы:

```text
                 pushed
                   │
                   ▼
            ┌─────────────┐
            │  Добавить   │
            │  в стек     │
            └──────┬──────┘
                   │
                   ▼
            ┌───────────────────┐
            │ Вершина ==        │
            │ popped[matched] ? │
            └──────┬────────────┘
                 Да│       │Нет
                   │       │
                   ▼       │
            ┌─────────────┐│
            │   pop()     ││
            └──────┬──────┘│
                   │       │
                   ▼       │
            Следующий      │
            popped[matched]│
                   │       │
                   └───┬───┘
                       ▼
                  Следующий
                  pushed
```

И алгоритм очень коротко:

Можно извлечь только элемент с вершины стека. Если очередной элемент `popped` не совпадает с вершиной стека, а добавить новые элементы уже нельзя, такая последовательность невозможна.

---
### и более длинное описание примера корректной последовательности

```text
pushed = [1, 2, 3, 4, 5]
popped = [1, 3, 5, 4, 2]
```

Пошагово:

```text
push(1)

┌───┐
│ 1 │ ← top
└───┘

pop(1)

┌───┐
│   │
└───┘
```

Добавляем `2` и `3`:

```text
push(2)
push(3)

┌───┐
│ 3 │ ← top
├───┤
│ 2 │
└───┘
```

В `popped` сейчас находится `3`, поэтому можем выполнить `pop(3)`:

```text
pop(3)

┌───┐
│ 2 │ ← top
└───┘
```

Далее добавляем `4` и `5`:

```text
push(4)
push(5)

┌───┐
│ 5 │ ← top
├───┤
│ 4 │
├───┤
│ 2 │
└───┘
```

В `popped` следующим находится `5`, поэтому:

```text
pop(5)

┌───┐
│ 4 │ ← top
├───┤
│ 2 │
└───┘
```

Следующим нужно извлечь `4`:

```text
pop(4)

┌───┐
│ 2 │ ← top
└───┘
```

```text
pop(2)

┌───┐
│   │
└───┘
```

Все элементы удалось извлечь в требуемом порядке.

Результат: True


---

### Пример некорректной последовательности

```text
pushed = [1, 2, 3]
popped = [3, 1, 2]
```

Добавляем элементы:

```text
push(1)
push(2)
push(3)

┌───┐
│ 3 │ ← top
├───┤
│ 2 │
├───┤
│ 1 │
└───┘
```

Первым нужно извлечь `3`, поэтому:

```text
pop(3)

┌───┐
│ 2 │ ← top
├───┤
│ 1 │
└───┘
```

Теперь в `popped` следующим находится `1`.

Но удалить `1` не можем, тк он находится не на вершине:

```text
┌───┐
│ 2 │ ← top     ← можно удалить только 2
├───┤
│ 1 │           ← 1 пока недоступен
└───┘
```

Поэтому получить последовательность `3, 1, 2` нельзя.

Результат: False
