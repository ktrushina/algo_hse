# Tracer — декоратор для отслеживания рекурсии

## Задание

Реализовать декоратор, который показывает стек вызовов рекурсивной функции.

При каждом вызове декоратор должен выводить:
- Вход в функцию с её аргументами.
- Отступ, соответствующий текущей глубине рекурсии.
- Возврат из функции с полученным результатом.
  
## Входные и выходные данные

Декоратор `tracer(func)` принимает функцию `func`, вызовы которой необходимо отслеживать.

Внутренняя функция `wrapper(*args, **kwargs)` принимает:
- `*args` — позиционные аргументы исходной функции.
- `**kwargs` — именованные аргументы исходной функции.

Декоратор возвращает функцию-обёртку `wrapper`, которая вызывает исходную функцию, выводит информацию о её выполнении и возвращает тот же результат

## Описание 

**Идея:** декоратор оборачивает исходную функцию и отслеживает глубину её рекурсивных вызовов с помощью счётчика

Алгоритм работает следующим образом:

1. Создаём список `depth = [0]`, в котором хранится текущая глубина рекурсии.
2. При входе в функцию формируем строку с аргументами и создаём отступ из двух пробелов на каждый уровень глубины.
3. Выводим имя функции и аргументы со стрелочкой `→`.
4. Увеличиваем глубину на 1 и вызываем исходную функцию.
5. После получения результата выводим его со стрелочкой `←` и тем же отступом, что был при входе.
6. Уменьшаем глубину на 1 при завершении вызова.

Конструкция `try/finally` гарантирует восстановление счётчика глубины даже при возникновении ошибки.

## Пример использования

Рассмотрим рекурсивную функцию вычисления факториала.

```python
# Пример рекурсивной функции с декоратором
@tracer
def factorial(n):
    # Базовый случай: останавливаем рекурсию
    if n <= 1:
        return 1

    # Рекурсивно вычисляем факториал
    return n * factorial(n - 1)


factorial(4)
```

**Результат выполнения:**

```text
→ factorial(4,)
  → factorial(3,)
    → factorial(2,)
      → factorial(1,)
      ← factorial = 1
    ← factorial = 2
  ← factorial = 6
← factorial = 24
```
**Обозначения:**

- `→` — вход в функцию, начало её выполнения.
- `←` — завершение вызова и возврат результата.
- Каждые два пробела перед стрелочкой соответствуют одному уровню вложенности.
  
## Визуализация 

Рассмотрим вычисление `factorial(4)`.

**Этап 1. Вход в рекурсию**

Каждый следующий вызов увеличивает глубину рекурсии на 1.

```text
factorial(4)                 depth = 0
    |
    └── factorial(3)         depth = 1
            |
            └── factorial(2) depth = 2
                    |
                    └── factorial(1) depth = 3
```

**Этап 2. Возврат из рекурсии**

После достижения базового случая результаты возвращаются в обратном порядке.

```text
factorial(1) = 1
      ↓
factorial(2) = 2 * 1 = 2
      ↓
factorial(3) = 3 * 2 = 6
      ↓
factorial(4) = 4 * 6 = 24
```

**Вывод:** при углублении рекурсии отступ увеличивается, а при возврате уменьшается. Благодаря этому можно визуально проследить порядок вызовов и возвращаемые результаты.

Рассмотрим выполнение `factorial(3)` и проследим изменение счётчика `depth[0]` в декораторе.

## И еще одна визуализация работы алгоритма
| Шаг | Действие в `wrapper` | `depth[0]` после действия | Вывод |
|---|---|---|---|
| 1 | Вход в `factorial(3)`, увеличение глубины | 1 | `→ factorial(3)` |
| 2 | Вход в `factorial(2)`, увеличение глубины | 2 | `  → factorial(2)` |
| 3 | Вход в `factorial(1)`, увеличение глубины | 3 | `    → factorial(1)` |
| 4 | Достижение базового случая и вывод результата | 3 | `    ← factorial = 1` |
| 5 | Выполнение `finally` после `factorial(1)` | 2 | — |
| 6 | Вывод результата `factorial(2)` | 2 | `  ← factorial = 2` |
| 7 | Выполнение `finally` после `factorial(2)` | 1 | — |
| 8 | Вывод результата `factorial(3)` | 1 | `← factorial = 6` |
| 9 | Выполнение `finally` после `factorial(3)` | 0 | — |

Отступ для каждого вызова вычисляется **до увеличения** счётчика `depth[0]`. При возврате используется сохранённый отступ `indent`.

## Оценка сложности

Обозначения:
- `n` — количество вызовов функции
- `h` — максимальную глубину рекурсии

**По времени: O(n · h)**

Для каждого вызова декоратор формирует отступ, длина которого зависит от текущей глубины рекурсии. В худшем случае создание отступа занимает `O(h)`.

Поэтому для `n` вызовов верхняя оценка дополнительных временных затрат составляет `O(n · h)`.

**По памяти: O(h)**

Для каждого вложенного вызова создаётся отдельный стековый кадр функции `wrapper`. Одновременно может существовать до `h` таких кадров.

Сам список `depth` занимает `O(1)` памяти.

Оценки относятся к дополнительным расходам декоратора без учёта вычислений исходной функции, размера аргументов и возвращаемых значений.



**Итог:** Декоратор `tracer` позволяет отслеживать порядок рекурсивных вызовов, их глубину, переданные аргументы и возвращаемые результаты.

Реализация сохраняет результат исходной функции, восстанавливает глубину после завершения вызова или возникновения исключения и не требует дополнительных библиотек.
