# K-th

## Вход и результат

В решении вход — список целых чисел

В списке из n элементов k-й по убыванию стоит на позиции target = n − k при индексации с нуля по возрастанию. Quickselect берёт последний элемент диапазона как опорный и разбивает текущий диапазон. Если target попал в блок равных, ответ уже известен. Если target левее или правее, продолжаем только с соответствующей частью. Границы хранятся в индексах исходной копии, поэтому target при сужении остаётся прежним

**Общий пример.** Для [4, 1, 5, 2, 3] и k = 2 нужен индекс 5 − 2 = 3

| lo, hi | Опорный | Массив после partition | lt, gt | Решение |
|---|---:|---|---|---|
| 0, 4 | 3 | [1, 2, 3, 5, 4] | 2, 2 | 3 > 2, присваиваем lo = 3 |
| 3, 4 | 4 | [1, 2, 3, 4, 5] | 3, 3 | Искомый индекс в блоке равных, возвращаем 4 |

**Сложность.** При сбалансированных разбиениях время O(n): длины проходов уменьшаются как n, n/2, n/4, … . Для равномерно случайной перестановки различных элементов среднее время также O(n). Худшее время O(n²), если каждый проход исключает только один элемент. Память O(n) на копию входного списка и O(1) на индексы


### Что делает один вызов partition

Общий вход для трёх задач — `[4, 1, 5, 2, 3]`. При опорном 3 индексы слева от lt уже содержат значения меньше 3, участок от lt до i исключительно содержит равные, правее gt лежат большие. Осталось проверить позиции от i до gt включительно

| Действие | lt, i, gt после действия | Массив |
|---|---|---|
| Начало | 0, 0, 4 | [4, 1, 5, 2, 3] |
| 4 > 3, меняем позиции 0 и 4 | 0, 0, 3 | [3, 1, 5, 2, 4] |
| 3 = 3, двигаем i | 0, 1, 3 | [3, 1, 5, 2, 4] |
| 1 < 3, меняем позиции 0 и 1 | 1, 2, 3 | [1, 3, 5, 2, 4] |
| 5 > 3, меняем позиции 2 и 3 | 1, 2, 2 | [1, 3, 2, 5, 4] |
| 2 < 3, меняем позиции 1 и 2 | 2, 3, 2 | [1, 2, 3, 5, 4] |

После обмена с gt оставляем i на месте, чтобы проверить число, которое пришло справа. Когда i > gt, все числа уже проверены и цикл заканчивается. Тройка встречается один раз и стоит на индексе 2, поэтому функция возвращает (2, 2)

**Оптимальность.** Линейное время при удачных разбиениях оптимально по порядку роста. Например, уже при k = 1 для поиска максимума приходится проверить каждый элемент. Гарантии линейного времени в худшем случае у этой версии нет.
