# Iterative

## Вход и результат

Вход — список целых чисел. Сортировка возвращает новый список по возрастанию и сохраняет исходный

**Mergesort.** Начинаем с готовых отсортированных блоков длины 1. Сливаем соседние пары и удваиваем ширину. После прохода с шириной w каждый блок длины до 2w отсортирован. Последний блок может быть короче, что естественно учитывается срезами Python

| Ширина перед проходом | Блоки после прохода |
|---:|---|
| Вход | [4] · [1] · [5] · [2] · [3] |
| 1 | [1, 4] · [2, 5] · [3] |
| 2 | [1, 2, 4, 5] · [3] |
| 4 | [1, 2, 3, 4, 5] |

### Последнее слияние общего примера

Вызов `merge([1, 2, 4, 5], [3])`. Индексы `i` и `j` указывают на первые ещё не взятые элементы. В таблице приведены значения **после** указанного действия

| Действие | i | j | result |
|---|---:|---:|---|
| Вход в merge | 0 | 0 | [] |
| 1 ≤ 3, берём слева | 1 | 0 | [1] |
| 2 ≤ 3, берём слева | 2 | 0 | [1, 2] |
| 4 > 3, берём справа | 2 | 1 | [1, 2, 3] |
| После выхода из while добавляем `left[i:]` = [4, 5] | 2 | 1 | [1, 2, 3, 4, 5] |
| После выхода из while добавляем `right[j:]` = [] | 2 | 1 | [1, 2, 3, 4, 5] |

**Quicksort.** Храним в стеке пары индексов (lo, hi), включая обе границы. Снимаем пару, разбиваем диапазон той же функцией partition и кладём в стек две крайние части. Большую кладём первой, чтобы сразу обработать меньшую. Пустые и одноэлементные диапазоны пропускаем. Когда стек опустел, все части упорядочены

| Шаг на том же входе | Состояние |
|---|---|
| В стеке (0, 4) | Разбиваем по 3. Получаем [1, 2] · [3] · [5, 4] |
| В стеке (0, 1), (3, 4), вершина справа | Снимаем (3, 4), разбиваем по 4. Список становится [1, 2, 3, 4, 5] |
| После пропуска коротких частей снимаем (0, 1) | Разбиваем [1, 2] по 2. Оставшиеся диапазоны имеют длину 0 или 1, стек опустошается |

## Сложность

| Версия | Время | Дополнительная память, включая возвращаемый список |
|---|---|---|
| Mergesort, итеративная | O(n log n) | O(n) на копию, срезы и слияние |
| Quicksort, итеративная | В среднем по случайным перестановкам O(n log n), в худшем O(n²), на одинаковых O(n) | O(n) на копию входа, явный стек O(log n) |

Mergesort обрабатывает O(n) элементов на каждом из O(log n) уровней. При слиянии одновременно хранятся копия a, срезы двух блоков, result и срез остатка. Вместе они занимают O(n), а следующая пара обрабатывается после предыдущей.

У quicksort сбалансированные разбиения дают O(n log n) времени, а последовательность размеров n, n−1, …, 2 даёт O(n²). Пока обрабатывается меньшая часть, большая ожидает в stack. Размер меньшей убывает как минимум вдвое при каждом таком вложении, поэтому одновременно ожидают O(log n) пар индексов

### Что делает один вызов partition

Общий вход для трёх задач — `[4, 1, 5, 2, 3]`. При опорном 3 индексы слева от lt уже содержат значения меньше 3, участок от lt до i исключительно содержит равные, правее gt лежат большие. Осталось проверить позиции от i до gt включительно

| Действие | lt, i, gt после действия | Массив |
|---|---|---|
| Начало | 0, 0, 4 | [4, 1, 5, 2, 3] |
| 4 > 3, меняем позиции 0 и 4 | 0, 0, 3 | [3, 1, 5, 2, 4] |
| 3 = 3, двигаем i | 0, 1, 3 | [3, 1, 5, 2, 4] |
| 1 < 3, меняем позиции 0 и 1 | 1, 2, 3 | [1, 3, 5, 2, 4] |
| 5 > 3, меняем позиции 2 и 3 | 1, 2, 2 | [1, 3, 2, 5, 4] |
| 2 < 3, меняем позиции 1 и 2 | 2, 3, 2 | [1, 2, 3, 5, 4] |

После обмена с gt оставляем i на месте, чтобы проверить число, которое пришло справа. Когда i > gt, все числа уже проверены и цикл заканчивается. Тройка встречается один раз и стоит на индексе 2, поэтому функция возвращает (2, 2)
**Оптимальность.** Mergesort достигает оптимальной для сортировок сравнениями оценки O(n log n) в худшем случае. Выбор последнего опорного у quicksort даёт воспроизводимый худший случай на возрастающем входе. Обработка меньшей части первой ограничивает стек, а выбор опорного определяет качество разбиений

Для каждого вызова берём свежую копию, проверяем сохранность входа и отдельный объект результата даже для пустого списка. Дополнительно сортируем 100 000 элементов в повторяющихся убывающих блоках.
