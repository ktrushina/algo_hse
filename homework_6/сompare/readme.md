# Compare

## Вход и результат

В решении вход — список целых чисел. Сортировка возвращает новый список по возрастанию и сохраняет исходный.

**Mergesort.** Делим список пополам до частей длины 0 или 1. Такие части уже упорядочены. При возврате из рекурсии функция merge сравнивает первые ещё не взятые элементы двух отсортированных половин и добавляет меньший в результат. Когда одна половина заканчивается, дописываем остаток другой. На каждом шаге выбирается наименьший из оставшихся элементов, поэтому результат слияния тоже упорядочен.

| Шаг на входе [4, 1, 5, 2, 3] | Состояние |
|---|---|
| Делим | [4, 1] и [5, 2, 3] |
| Разбираем левую половину | [4] и [1] дают [1, 4] |
| Разбираем правую половину | [2] и [3] дают [2, 3]. Слияние с [5] даёт [2, 3, 5] |
| Сливаем [1, 4] и [2, 3, 5] | Выбираем по очереди 1, 2, 3, 4 и дописываем 5 |

### Последнее слияние общего примера

Вызов `merge([1, 4], [2, 3, 5])`. Индексы `i` и `j` указывают на первые ещё не взятые элементы. В таблице приведены значения **после** указанного действия.

| Действие | i | j | result |
|---|---:|---:|---|
| Вход в merge | 0 | 0 | [] |
| 1 ≤ 2, берём слева | 1 | 0 | [1] |
| 4 > 2, берём справа | 1 | 1 | [1, 2] |
| 4 > 3, берём справа | 1 | 2 | [1, 2, 3] |
| 4 ≤ 5, берём слева | 2 | 2 | [1, 2, 3, 4] |
| После выхода из while добавляем `left[i:]` = [] | 2 | 2 | [1, 2, 3, 4] |
| После выхода из while добавляем `right[j:]` = [5] | 2 | 2 | [1, 2, 3, 4, 5] |

**Quicksort.** В качестве опорного берём последний элемент текущего диапазона. Функция partition создаёт три соседних блока со значениями меньше опорного, равными ему и больше него.

**Зачем выделять равные элементы?** После разбиения все меньшие значения уже слева, а все большие — справа. Значит, весь блок равных занимает свои окончательные позиции и его можно пропустить целиком. Например, для `[7, 7, 7, 7]` один проход сразу завершает сортировку за O(n).

**Почему рекурсивно обрабатываем меньшую часть?** Каждый вложенный вызов получает не более половины элементов текущего диапазона. Поэтому одновременно в стеке находится O(log n) вызовов. Большую часть обрабатывает цикл того же вызова. Например, при разбиении 1200 элементов на 1199 меньших и один опорный рекурсивный вызов на пустой части сразу вернётся, а цикл продолжит работу с 1199 элементами. Если такие разбиения повторяются, время всё ещё O(n²).


| Обрабатываемый диапазон | Опорный | Весь список после partition |
|---|---:|---|
| [4, 1, 5, 2, 3] | 3 | [1, 2] · [3] · [5, 4] |
| [5, 4] | 4 | [1, 2, 3, 4, 5] |
| [1, 2] | 2 | [1, 2, 3, 4, 5] |

**Как измеряли время.** Декоратор timed оборачивает внешний вызов, считывает default_timer до и после выполнения и возвращает пару (результат, секунды). Каждый метод получает одинаковый список длины 2500. Берём среднее по семи запускам и чередуем порядок методов. Генерация входа и проверка ответа выполняются за пределами замера.

| Вход | Mergesort, мс | Quicksort, мс | Объяснение |
|---|---:|---:|---|
| Числа по возрастанию | 4.898 | 494.244 | Последний элемент каждый раз максимален. После прохода остаются n−1 элементов в прежнем порядке |
| Все числа равны | 5.128 | 0.280 | У quicksort весь список попадает в средний блок за один проход. Mergesort выполняет все уровни слияния |


## Сложность

| Версия | Время | Память, включая возвращаемый список |
|---|---|---|
| Mergesort, рекурсивная | O(n log n) | O(n), включая срезы и результат слияния |
| Quicksort, рекурсивная | В среднем по случайным перестановкам O(n log n), в худшем O(n²), на одинаковых O(n) | O(n) на копию входа, стек вызовов O(log n) |

Mergesort обрабатывает O(n) элементов на каждом из O(log n) уровней. Срезы и отсортированные половины вдоль активной ветви занимают O(n) суммарно: их размеры убывают как n, n/2, n/4, … . Результат слияния и срез остатка также помещаются в O(n). Декоратор timed добавляет O(1) времени и памяти к одному внешнему вызову.

У quicksort сбалансированные разбиения дают O(n log n) времени, а последовательность размеров n, n−1, …, 2 даёт O(n²). Меньшая часть, передаваемая в рекурсию, содержит не более половины элементов, поэтому глубина стека — O(log n).

### Что делает один вызов partition

Общий вход для трёх задач — `[4, 1, 5, 2, 3]`. При опорном 3 индексы слева от lt уже содержат значения меньше 3, участок от lt до i исключительно содержит равные, правее gt лежат большие. Осталось проверить позиции от i до gt включительно.

| Действие | lt, i, gt после действия | Массив |
|---|---|---|
| Начало | 0, 0, 4 | [4, 1, 5, 2, 3] |
| 4 > 3, меняем позиции 0 и 4 | 0, 0, 3 | [3, 1, 5, 2, 4] |
| 3 = 3, двигаем i | 0, 1, 3 | [3, 1, 5, 2, 4] |
| 1 < 3, меняем позиции 0 и 1 | 1, 2, 3 | [1, 3, 5, 2, 4] |
| 5 > 3, меняем позиции 2 и 3 | 1, 2, 2 | [1, 3, 2, 5, 4] |
| 2 < 3, меняем позиции 1 и 2 | 2, 3, 2 | [1, 2, 3, 5, 4] |

После обмена с gt оставляем i на месте, чтобы проверить число, которое пришло справа. Когда i > gt, все числа уже проверены и цикл заканчивается. Тройка встречается один раз и стоит на индексе 2, поэтому функция возвращает (2, 2)

### Общий пример для сравнения

| Алгоритм | Что делает на [4, 1, 5, 2, 3] | Результат |
|---|---|---|
| Рекурсивная mergesort | Делит на [4, 1] и [5, 2, 3]. Последнее слияние объединяет [1, 4] и [2, 3, 5] | [1, 2, 3, 4, 5] |
| Итеративная mergesort | Сливает блоки ширины 1, 2, 4. Последнее слияние объединяет [1, 2, 4, 5] и [3] | [1, 2, 3, 4, 5] |
| Рекурсивная quicksort | После опорного 3 рекурсивно обрабатывает [5, 4], затем в цикле [1, 2] | [1, 2, 3, 4, 5] |
| Итеративная quicksort | Кладёт в стек (0, 1), затем (3, 4). Первым снимает (3, 4) | [1, 2, 3, 4, 5] |
| Quickselect, k = 2 | При опорных 3 и 4 ищет индекс 3 сначала в [0, 4], затем в [3, 4] | 4 |

**Оптимальность.** Mergesort достигает оптимальной для сортировок сравнениями оценки O(n log n) в худшем случае. Выбор последнего опорного у quicksort даёт воспроизводимый худший случай на возрастающем входе. Обработка меньшей части первой ограничивает стек, а выбор опорного определяет качество разбиений.



## Тесты

Проверяем обе сортировки на пустом списке, одном элементе, паре в обратном порядке, повторах, отрицательных числах, возрастающем, убывающем и входе нечётной длины. Для каждого вызова берём свежую копию, проверяем сохранность входа и отдельный объект результата даже для пустого списка. Дополнительно сортируем 100 000 элементов в повторяющихся убывающих блоках.
Отдельный тест проверяет результат декорированной функции и длительность вызова.
