# Binary Search Tree (BST)

## Объяснение решения

Каждый узел хранит значение и ссылки на левого и правого потомков.

BST поддерживает следующее правило:
- значения в левом поддереве узла меньше значения самого узла
- значения в правом поддереве больше значения самого узла

### Вставка элемента

Если дерево пустое, новый узел становится корнем. Иначе начинаем с корня и сравниваем новое значение со значением текущего узла:
- если новое значение меньше, переходим влево
- если больше — вправо
- если дошли до пустой ссылки, создаём там новый узел
- если значение уже есть, ничего не делаем — дубликаты не добавляются

Такое сравнение сохраняет свойства BST после каждой вставки

### Обходы дерева

Каждый обход рекурсивно посещает узлы и добавляет их значения в список `result`. Если текущий узел равен `None`, рекурсия заканчивается. Обход начинается с корня дерева.

Обходы отличаются порядком посещения текущего узла (`N`), левого поддерева (`L`) и правого поддерева (`R`):

| Метод | Порядок посещения |
|---|---|
| `preorder` | N → L → R |
| `inorder` | L → N → R |
| `postorder` | L → R → N |
| `reverse_preorder` | N → R → L |
| `reverse_inorder` | R → N → L |
| `reverse_postorder` | R → L → N |

Обратные обходы меняют местами левое и правое поддеревья по сравнению с соответствующими обычными обходами. В частности, `inorder` возвращает значения BST по возрастанию, а `reverse_inorder` — по убыванию

## Оценка сложности

- `n` — количество узлов дерева;
- `h` — высота дерева.

### Вставка

- **Время:** `O(h)`, потому что при вставке мы спускаемся от корня по одному пути вниз
- **Память:** `O(1)`, поскольку вставка использует несколько переменных и не создаёт дополнительных структур данных

Для сбалансированного дерева высота составляет `O(log n)`, поэтому вставка занимает `O(log n)`. В худшем случае, когда дерево вырождается в цепочку, высота равна `O(n)`, и вставка занимает `O(n)`

### Обходы

- **Время:** `O(n)`, тк каждый узел посещается ровно один раз
- **Память:** `O(n)` для списка результата. Дополнительно рекурсивные вызовы используют стек глубины `O(h)`

Следовательно, полная память обхода с учётом списка результата — `O(n)`, а доп память рекурсии — `O(h)`

## Визуализация работы алгоритма

Рассмотрим вставку значений в порядке:

`8, 3, 10, 1, 6, 14, 4, 7, 13`

### Пошаговая вставка

| Шаг | Вставляемое значение | Сравнения и действие |
|---:|---:|---|
| 1 | 8 | Дерево пустое: `8` становится корнем. |
| 2 | 3 | `3 < 8`: вставляем слева от `8`. |
| 3 | 10 | `10 > 8`: вставляем справа от `8`. |
| 4 | 1 | `1 < 8`, затем `1 < 3`: вставляем слева от `3`. |
| 5 | 6 | `6 < 8`, затем `6 > 3`: вставляем справа от `3`. |
| 6 | 14 | `14 > 8`, затем `14 > 10`: вставляем справа от `10`. |
| 7 | 4 | `4 < 8`, `4 > 3`, `4 < 6`: вставляем слева от `6`. |
| 8 | 7 | `7 < 8`, `7 > 3`, `7 > 6`: вставляем справа от `6`. |
| 9 | 13 | `13 > 8`, `13 > 10`, `13 < 14`: вставляем слева от `14`. |

После всех вставок дерево выглядит так:

```text
          8
        /   \
       3     10
      / \      \
     1   6      14
        / \    /
       4   7  13
```

### Пошаговый пример обхода `inorder`

Порядок `inorder`: левое поддерево → текущий узел → правое поддерево.

| Действие | Что происходит | Результат |
|---:|---|---|
| 1 | Идём от `8` влево к `3`, затем влево к `1`. У `1` нет левого потомка — записываем `1`. | `[1]` |
| 2 | Возвращаемся к `3` и записываем его после завершения левого поддерева. | `[1, 3]` |
| 3 | Переходим к правому поддереву `3`, то есть к `6`. Сначала посещаем его левого потомка `4`. | `[1, 3, 4]` |
| 4 | Записываем `6`, затем посещаем его правого потомка `7`. | `[1, 3, 4, 6, 7]` |
| 5 | Возвращаемся к корню `8` и записываем его. | `[1, 3, 4, 6, 7, 8]` |
| 6 | Переходим в правое поддерево `8`, к `10`. У него нет левого потомка, поэтому записываем `10`. | `[1, 3, 4, 6, 7, 8, 10]` |
| 7 | Переходим к `14`, сначала посещаем его левого потомка `13`, затем записываем `14`. | `[1, 3, 4, 6, 7, 8, 10, 13, 14]` |

Итоговый результат `inorder`:

```text
[1, 3, 4, 6, 7, 8, 10, 13, 14]
```

Значения идут по возрастанию, потому что по свойству BST все значения левого поддерева меньше значения узла, а все значения правого поддерева — больше

## И супер коротко важное из кода 

В каждом методе есть внутренняя функция `traverse(node)`. Она рекурсивно посещает узлы и записывает их значения в `result`.

Разница между обходами (!) `только в порядке выполнения трех действий`:
- `result.append(node.value)` — посетить текущий узел
- `traverse(node.left)` — обойти левое поддерево
- `traverse(node.right)` — обойти правое поддерево

Например, в `inorder` сначала вызывается обход левого поддерева, затем записывается текущий узел, а затем обходит правое поддерево. Поэтому для BST значения в результате будут отсортированы по возрастанию.

А `reverse_inorder` обходит правое поддерево первым, поэтому возвращает значения по убыванию.
